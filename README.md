> ที่นี่เหลือไว้เฉพาะโค้ดส่วนที่ระบบจริง**ยังไม่มี** เอาไว้ดูตอนเขียนหน้าลงสต็อกในระบบจริง

## ⚠️ ทำไมถึงห้าม deploy

เดิม repo นี้เป็นระบบสต็อกเต็มตัว ที่เขียนคู่ขนานกับระบบจริงโดยไม่รู้ว่ามีของเดิมอยู่แล้ว
พอเทียบกันแล้วซ้ำเกือบทั้งหมด และมีจุดที่**ทำให้ระบบจริงพัง**ถ้าเผลอเอาไปรันบนชีตเดียวกัน:

- ชีต **`ผู้ใช้งาน`** ชื่อเดียวกันทั้งสองระบบ แต่คอลัมน์ 4–6 สลับกัน
  (ของจริง `สาขา | ใช้งาน | สิทธิ์` — ของเดิมที่นี่อ่านเป็น `บทบาท | สาขา | เปิดใช้งาน`)
  และโค้ด `login()` อ่านตามตำแหน่งคอลัมน์ ไม่ได้อ่านตามชื่อหัวตาราง
- `login()` **เขียนทับช่องรหัสผ่าน**ด้วย hash คนละสูตรกับระบบจริง
  (ที่นี่ `sha256:` + base64 ของ salt+รหัส / ของจริง `sha256:` + hex ของรหัสเปล่า)
  ขึ้นต้นเหมือนกันทั้งคู่ ระบบจริงเลยนึกว่าเป็น hash ของตัวเอง → **user นั้นล็อกอินเข้า POS ไม่ได้อีกเลย**
- `doGet` ชื่อชนกับ `doGet` ของ `pos-backend.gs` ตรง ๆ
- `checkExpiryDaily` ซ้ำกับ `line-expiry-alert.gs` → ถ้ารันทั้งคู่ ไลน์เด้ง 2 รอบ

โค้ดส่วนที่ว่ามาทั้งหมดลบทิ้งไปแล้ว เหลือแต่ส่วนที่ไม่ซ้ำ

## มีอะไรเหลืออยู่

| ไฟล์ | เอาไว้ทำอะไร |
|---|---|
| `reference/stock-logic.gs` | แปลงหน่วยแพ็ค↔ไม้, คำนวณยอดคงเหลือ, เตือนของครัวกลางใกล้หมด |
| `reference/StockIn.html` | ฟอร์มของเข้าครัวกลาง (ช่องแพ็ค + เศษ) |
| `reference/ToShop.html` | ฟอร์มส่งของเข้าร้าน |
| `reference/Count.html` | ฟอร์มเช็คสต็อกรายสัปดาห์ (บังคับนับให้ครบ) |
| `reference/Waste.html` | ฟอร์มของเสีย |
| `reference/Common.html` `reference/Style.html` | ฟังก์ชันร่วมฝั่งหน้าเว็บ + สไตล์ |

หน้า HTML พวกนี้เป็นเทมเพลตของ Apps Script (`<?!= include(...) ?>`, `google.script.run`)
เปิดตรง ๆ ในเบราว์เซอร์ไม่ได้ และเรียกฟังก์ชันฝั่งเซิร์ฟเวอร์ที่ลบไปแล้ว — **ดูเป็นแบบอย่างเท่านั้น**

## หัวใจของโค้ดที่เหลือ

**หน่วยนับ 2 ระดับ** — เก็บยอดจริงเป็นหน่วยย่อยเสมอ แปลงกลับเป็นแพ็คตอนแสดงผล บวกลบข้ามแพ็คได้ไม่เพี้ยน

```
ลูกชิ้น 1 ถุง = 26 ชิ้น  →  เสียบได้ 26 ไม้  →  แพ็คละ 7 ไม้
                                    ↓
                    ลงสต็อก "3 แพ็ค 5 ไม้"   (ระบบเก็บจริงเป็น 26 ไม้)
                                    ↓
              ส่งเข้าร้าน 1 แพ็ค  →  ระบบรู้ว่า = 7 ไม้  →  ครัวกลางเหลือ 2 แพ็ค 5 ไม้
```

**เตือนของใกล้หมด** — `checkLowStock_` เตือนตอน "ตกลงมาต่ำกว่าจุดเตือน" ครั้งเดียว
แล้วจำสถานะไว้ใน Script Properties จนกว่าจะเติมของ ไม่ใช่เตือนทุกครั้งที่ส่งของออก

## ตอนยกไปใช้ในระบบจริง ต้องแก้ 2 อย่าง

1. **ชื่อชีตและคอลัมน์** — ระบบจริงใช้ `จำนวนของเข้า` · `เช็คสต็อกรายสัปดาห์` · `ของเสีย` · `ยอดขาย`
   ทั้ง `line-expiry-alert.gs` และ `loss-calculator.html` หาคอลัมน์จาก**ชื่อหัวตาราง** ไม่ใช่ตำแหน่ง
   → เติมคอลัมน์ `แพ็ค` / `เศษ(ไม้)` เข้าไปได้เลย ของเดิมไม่พัง
2. **การส่ง LINE** — ใช้ `sendLine_` ใน `line-expiry-alert.gs` แทน `linePush_` ที่นี่
   จะได้มี channel access token อยู่ที่เดียว
